# 性能与容量验证

## 数据库查询

SQLite 使用 WAL，每个应用上下文持有独立连接。连接启用外键约束和 `synchronous=NORMAL`，锁等待上限为 30 秒。任务认领使用短事务，文档解析、模型请求和文件处理在事务外执行。

Web 请求在线程内创建独立应用上下文，数据库连接和身份缓存限于本次请求。响应正文迭代与关闭均在该上下文中完成，正常响应和异常响应都在创建连接的线程内释放连接。

查询索引由 `app/persistence/schema.py` 统一定义。新建表时创建完整索引，已有表在启动时补齐缺少的性能索引。表、字段、索引和触发器的定义由数据库结构契约测试验证。

| 场景 | 执行策略 |
| --- | --- |
| 用户任务列表 | 使用任务类型、用户主体及创建时间的组合索引，按页读取展示字段，仅多文档任务读取分组元数据；状态汇总使用类型、用户主体及状态的覆盖索引，同时提供分页总数 |
| 状态轮询 | 按指定任务 ID 批量查询状态与统计，单次最多 100 个 ID；有效统计直接使用，已结束且统计过期的任务按主键检查报告存在性；用户计数使用状态覆盖索引，用户条件约束数据归属 |
| 管理日期统计 | 按支持的任务类型和时间范围查询，使用类型与创建时间索引 |
| 模型配置 | 按用户主体批量读取提供商及其模型，两次查询完成全部配置加载；选择模型时按提供商主键和用户归属定位 |
| 队列认领 | 通过状态与用户索引逐个定位排队用户，排除达到并发上限的用户；只对每个用户的有限候选做排序 |
| 报告汇总 | 使用 SQLite `SUM` 聚合持久化统计字段，页面同步准备最近最多 20 个任务的报告统计 |
| 后台报告统计 | 使用主键游标，每轮检查最多 512 个任务，更新最多 100 个过期报告；游标循环覆盖历史记录 |
| 文件清理 | 使用已结束且文件尚未清理任务的部分索引，按清理时间取有限批次；文件缓存管理页使用同一索引读取候选元数据 |
| 删除任务 | 按任务 ID 索引定位并删除关联的误报命中记录 |
| 误报规则 | 启用规则使用类型与更新时间的部分索引，规则版本统计直接读取索引 |

### 启动索引检查

性能索引均为非唯一索引：

| 索引 | 定义 |
| --- | --- |
| `idx_tasks_type_owner_status` | `tasks(task_type, owner_subject, status)` |
| `idx_tasks_pending_file_cleanup` | `tasks(source_files_cleaned_at, COALESCE(finished_at, updated_at, created_at), id)`，仅包含文件未清理且状态为 `completed`、`partial`、`failed`、`canceled` 的任务 |
| `idx_report_suppression_hits_task` | `report_suppression_hits(task_id)` |
| `idx_report_suppression_rules_enabled_type_updated` | `report_suppression_rules(task_type, updated_at)`，仅包含 `enabled = 1` 的规则 |

已有表的检查读取 SQLite 索引元数据，仅补建缺少的索引。补建与相关表的 `ANALYZE` 在初始化写事务中完成，每张受影响的表分析一次。索引完整时跳过补建和分析。创建索引与分析需要读取已有数据，部署时为首次初始化预留时间；索引会占用磁盘空间，并由 SQLite 在相关数据写入时维护。

`ANALYZE` 使用 SQLite 自身的统计元数据，业务表和字段保持不变。新库索引定义与已有表的兼容逻辑共用 `QUERY_INDEXES`；兼容逻辑的位置和清理范围见 [开发与模块边界](development.md)。

### 查询边界

任务列表按 `created_at DESC, id DESC` 排序。原始文档正文和报告正文由预处理、检查或报告详情按需读取。

报告统计使用任务更新时间和规则版本判断有效性，报告写入通过数据库触发器删除统计缓存。查询优先使用已有统计行，报告重算按任务主键读取原始结果。当前页可同步准备统计，后台游标持续刷新历史报告。汇总值由已经持久化的统计提供，规则批量调整后的历史统计随后台处理逐步更新。

精确历史汇总需要遍历筛选范围内的统计记录；包含匹配的关键词检索需要检查范围内的文件名和对照任务元数据，console 还会检查身份信息。查询成本受所选数据范围影响。管理概览通过日期过滤控制范围；深页 `OFFSET` 查询的成本随页码增加。容量评估应同时覆盖典型用户历史量和管理员实际筛选范围。

## 文档处理

- 文档文本、图片与视频产物在任务进程中处理，预处理结果写入任务记录供后续检查与重试复用。
- 监督器按任务主键和令牌维护租约，续约独立于任务进程中的解析线程。任务进程确认退出后释放并发名额。
- 任务使用独立 Python 模块入口，进程创建后 60 秒内确认业务就绪。启动超时会终止进程并记录失败原因；已就绪的文档处理按租约持续执行，日志记录启动阶段与文档处理耗时。
- 受管理任务参与全局和用户并发统计；队列查询按状态索引和少量任务主键合并记录，回归测试覆盖一万条历史记录与一万条受限用户排队记录。
- PDF 在页与表格行边界、Excel 在行边界检查取消，停止继续解析后续内容。任务日志记录预处理总耗时和文本长度。
- PDF 文本使用 PyMuPDF 提取；按页按需使用 pypdf 回退，并保留表格与链接证据。
- PDF 表格通过已有字符边界索引筛选含文字候选的单元格。字符边界按顶部排序，使用底部前缀最大值二分定位相邻候选；候选存在时使用原生文本回退，同页表格共用 TextPage。字符信息不完整时保留回退。
- PDF 图片和有效绘图先按面积与尺寸过滤，再按纵向中心坐标索引；单元格检查相邻候选并沿用坐标容差和内缩边界。
- PDF 空格修正通过前后各一次字符遍历确定相邻正文字符，计算量随行长度线性增长。
- 词条命中位置直接二分查找页面和工作表索引，单次定位的标记查找成本为对数级。
- 图片任务的 PDF 文本提取跳过表格结构化。页面渲染数量受图片检查配置限制。
- `xlsx`、`xlsm` 使用一个只读工作簿，单次单元格解析同时读取缓存值和公式。超链接按行列活动范围索引，重叠范围按声明顺序选择；行内空位保留，连续空白区域跳过，列展开以实际内容和链接范围为界。`xls` 使用 xlrd 按行提取。
- 视频采样使用有界的两路 `ffmpeg` 抽帧，并保持帧顺序和失败回退。

## 证据审查的效率与质量

文本来源在任务内构建一次，同页同章节的连续正文保留行号合并。各检查项根据正文、提示词与契约的总输入选择全文核查或分批执行。全文核查直接生成候选；分批一致性与对照检查抽取事实并执行全局比较。候选数量与补充取证决定后续复核调用量。

分批发现、全局对照和首轮复核每次最多 3 批并行，所有检查项共用任务范围内的 3 个模型请求名额。规划、属性对齐与工具循环按依赖执行。独立对照组按字符预算合并发送；每批响应立即保存，并按原文顺序验证和合并，失败续跑复用已返回批次。局部表达和单纯一致性检查按所需范围生成输出，完整性与规范核查保留逐项覆盖观察。

图片和视频任务的独立批次最多 3 批并行，图片的不同检查组共用请求名额。每个请求线程持有独立应用上下文；流式快照和完成结果交回所属执行线程保存。流式缓冲只保留每批最新内容，完成批次按来源顺序排列；取消或快照异常会停止剩余请求并释放名额。

每次模型调用受提供商的输入字符配置、连接与读取等待超时和上游默认输出容量约束，单项执行受内置候选数量、审查轮次和有限重试约束。线上任务持续完成分批覆盖，累计请求次数、时间和 token 用于统计。规划根据业务提示词选择所需全文核查，局部表达跳过全局对照。工具返回请求来源、表头与相邻内容，并记录截断；要求观察按状态统计和分批提供，保留全局已覆盖与不确定计数。大型事实组的跨批次对照会增加请求与耗时。

模型接口返回的实际输入、输出 token 用于记录和统计，缺少用量时保留统计不完整标记。协议不兼容、HTTP 重试和一次结构修复均计入累计请求次数。线上报告展示实际已知用量，离线评测支持显式累计执行预算，并在提供单价与完整用量时计算成本。

文本审查的规划、发现、对照和独立复核统一控制思考成本。DeepSeek 使用关闭思考参数，其他模型的中高强度降为 `low`。请求记录包含实际思考强度与关闭状态。高思考强度可能消耗大量输出 token；调优同时核对发现候选、证据复核与人工标注召回。

`scripts.evaluate_checks` 在同一组人工标注文档上测量整文和证据审查的准确率、关键问题召回率、每文档误报数、P50/P95 耗时及已知 token、成本。线上验收同时检查完整标注、执行成功率和质量门槛；业务取舍由实际测量确定。命令、样本格式和反馈导出见 [证据审查与评估](evidence-agent.md)。

## 并发边界

Windows 和 Linux 统一使用 Uvicorn 和 a2wsgi 请求线程池，默认 1 个 Web 进程、每进程 16 个请求线程。`server.web_threads` 控制每进程请求线程数，`server.web_workers` 控制 Web 进程数。HTTP 并发负责页面、上传和轮询；任务执行并发由 `global_concurrency`、`user_concurrency` 和 `worker.max_task_processes` 共同控制。`check_item_concurrency` 控制单任务同时执行的检查项，文本审查的模型请求共用内置 3 个名额，检查项并发与批次并行度共同遵守这个请求上限。

100 个用户访问页面与 100 个任务同时解析或调用模型对应不同的资源需求。任务进程上限控制文档解析的 CPU 和内存消耗；模型任务吞吐还取决于输入长度、图片批次、模型服务限流和响应时间。

## 可复现的 HTTP 压测

从项目根目录执行：

```bash

```

## 执行阶段轮询

任务阶段记录独立于报告正文，以任务主键和 `settings.key` 唯一索引定位。模型流只在等待、思考、输出、重试等阶段变化时更新记录，取消监测每任务每秒读取一次紧凑状态。任务列表按当前页任务 ID 批量读取，详情页每 10 秒获取轻量状态；报告版本变化时才加载并渲染结果正文。单项取消复用现有监测线程，检查项开始时复用一次短写事务确认取消意图，待执行的已取消项直接跳过；排队记录在任务认领事务内按唯一键更新执行令牌。确认气泡打开时详情暂缓替换内容，模型输出仍按游标增量读取。图片和视频的请求分组保持一致。

单项手动重试复用任务线程池和检查项并发上限，等待旧执行退出后才重新提交；任务进程每秒按主键读取一次紧凑活动状态，仅在接收重试或结束任务时进入短写事务。已结束任务的单项重试受原任务队列并发限制。重试接口按任务主键加载快照与结果，不读取文档全文；文档预处理复用已有解析缓存，其他检查项结果继续保留。


模型输出使用独立追加文件，每任务共享缓冲和写锁，合并请求复用同一份记录；输出采集按 0.25 秒或 4,096 字符刷新，请求结束时写完尾部。查看接口按任务主键验证权限，跳过报告长度计算与报告解析，按字节游标读取至多 64 KiB 的完整记录。展开时约每秒发起短请求；活动任务折叠时仅读取按主键定位的检查状态，跳过输出文件和报告解析，后台标签页暂停请求。单页多个展开区共用一次读取。报告保持 10 秒刷新，检查状态用于及时清理自动重试的旧错误与输出；输出区按检查项保留最新请求的文本，释放旧请求的浏览器缓存与 DOM，增量追加时保留阅读位置。

任务筛选与分页采用局部请求，省略新建任务表单以及模型和检查项目录查询。用户查询通过任务归属与类型索引限定候选记录后执行筛选；普通用户的关键词只检查文件名，对照任务按 JSON 路径补充各个文件名。console 的关键词同时检查用户信息。标注状态基于已有统计缓存，前台最多准备最近 20 条用户任务的统计。表格更新复用表头和未变化的行；连续筛选取消旧请求并忽略过期响应。无筛选的自动刷新继续优先使用轻量状态接口。

批量重试在同一短事务内按任务主键读取最新快照与结果，按原提供商主键获取访问密钥，只重跑失败、已取消及原执行范围内缺少结果的项。成功结果与标注复用，排队状态通过 `settings.key` 唯一索引写入；事务内完成数据库操作，模型请求和文档处理由任务进程执行。
