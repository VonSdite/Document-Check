# 专项 skill 与问题案例

单文档检查同时提供现有检查项和专项 skill。现有检查项执行宽泛检查，专项 skill 使用明确的判定方法识别已确认的问题模式。常用词、敏感词和超链接检查继续使用各自的程序规则。

## 创建专项

拥有公共规则管理权限的用户在“公共规则 → 专项 skill”填写专项名称和适用范围说明，创建草稿。超级管理员也可以从系统设置进入。

规则编辑包含检查目标、适用条件、判断步骤、必要证据、排除条件和修改建议原则。系统统一提供报告格式、原文定位、证据门槛和文档解析限制。保存完整规则后，可以展开实际执行提示词。

启用前至少录入一条已人工确认的真实问题案例。启用后，专项显示在单文档任务的检查项列表中，可以与现有检查项一起选择。删除或取消确认最后一条已确认真实问题时，专项自动停用。

## 提供案例

每条案例填写：

- 案例名称与类型：真实问题，或应当放行的正确反例。
- 文档、版本及适用场景：标明产品、型号、运行模式和相关条件。
- 证据位置与原文证据：保留原句和必要上下文；一致性问题提供两处原文。
- 确认理由与权威依据：解释问题为什么成立，或反例为什么正确；业务规范同时说明来源与适用范围。
- 期望检查结果：说明应报告的具体问题，或明确反例应当放行。
- 验证文本：粘贴完整验证上下文。信息缺失案例需要核对全文及相关引用内容。
- 确认后的修改内容：可选填写经过核实的正确表述。

勾选人工确认后，案例可以作为提示词示例。每次检查最多引用两条真实问题和两条正确反例，各示例字段最多引用 400 字。完整验证文本保存在案例库中，供独立验证任务使用。

报告条目的“固化为案例”链接会进入专项列表。选择目标专项后，页面带入来源任务、原文、位置、问题描述和可用的全文。补充适用场景、确认理由与期望结果后保存。来源报告案例先作为待确认内容处理。全文已清理时，在验证文本中补齐完整上下文。

人工发现的漏报通过专项页面直接新增真实问题案例。模型误报可以整理为正确反例，并说明应放行的具体条件。

## 验证与版本

在案例库选择当前用户的可用模型，点击“执行案例验证”。系统以完整验证文本创建独立单文档任务，使用当前专项规则和其余代表性示例；被验证案例自身从提示词示例中排除。验证使用任务队列、取消、重试和报告功能，打开验证报告后人工对照期望结果。

规则或案例修改会更新版本。页面显示上次验证任务与版本，规则更新后可以重新验证。版本预览、案例验证和人工复核共同帮助确认适用边界。

普通任务提交时保存专项版本、完整规则、实际提示词和示例案例编号。后台执行与重试使用任务快照。案例及规则存储在 `instance/` 的 SQLite 数据库中。

系统设置提供“含专项 skill 的单任务报告条数上限”，`0` 表示展示全部条目，正整数在合并后限制整个任务的报告条数。任务提交时同时保存该设置，原始结果与人工反馈继续保留。

## 报告合并

有专项参与时，系统按相同原文证据、相同问题描述和相同判定类型合并跨检查项重复条目，汇总位置并展示共同发现的检查项及专项版本。证据或描述不同的条目分别保留。常用词、敏感词和超链接结果使用各自的报告处理。

已提交的人工反馈继续保留；存在相互冲突的人工反馈时，条目分别展示。原始模型回复始终保存，HTML 和 Excel 报告展示合并后的问题与来源。
