# 检查规则库交互原型

原型展示人工反馈、规则草稿、正反案例验证、审核发布、文档试运行和复核积累的完整流程。页面使用内置示例数据，操作记录保存到当前浏览器的独立存储空间，支持导出 JSON 和重置。

## 打开方式

- 在工具的“设置”或“公共规则”页面点击“检查规则库原型”。
- 直接用浏览器打开 `app/web/static/rule-library-prototype/index.html`。
- 服务运行时访问 `/static/rule-library-prototype/index.html`，部署有路径前缀时使用设置页入口。

原型静态资源仅包含虚构示例，可独立打开。真实报告、用户身份、数据库、模型配置及现有误报规则继续使用项目现有流程。

## 推荐体验顺序

1. 在“流程总览”点击“从一个已认可案例开始”，查看 C-001 的两处额定电压证据，生成检查规则草稿。
2. 运行案例验证，观察“合理例外”场景失败；关联 C-002 误报反例，补充不同工况允许不同参数的例外条件。
3. 再次验证，确认真实问题、合理例外、修复后内容、条件不明和引用无依据等场景符合预期。
4. 提交审核，确认适用范围、正反案例和证据要求，发布并启用 v1。
5. 在“文档试运行”切换六种示例情境。真实问题与旧误报描述相似时，原型保留问题并提示复核；明确例外单独展示；无法取证的结论保持待确认。
6. 填写当前原文支持的复核依据。认可或不认可产生新案例，待确认保留原条目。新案例通过整理和审核进入规则。
7. 修改规则草稿或停用规则，在“复核与记录”检查此前试运行的版本快照。

“规则库”的 L-001 模拟已有误报规则，支持关联同主题检查规则、补充例外并保留历史来源。C-004 展示认可建议的补证确认；C-005 展示幻觉反馈作为证据校验案例收集。

## 数据与判定范围

案例保存原文、人工反馈、文档上下文和规则关联。检查规则保存范围、判错条件、证据要求、例外条件、案例来源、草稿及发布版本。试运行保存文档场景、规则快照、原始判定和独立的人工复核记录。

参数一致性和术语检查采用固定结构的预设场景。产品、文档类型、例外开关及发布状态影响模拟执行；自然语言条件作为审核说明展示。其他主题支持案例整理和草稿保存，启用需要补充相应验证场景。原型验证用于体验流程；正式规则的效果评估需要额外使用人工核实的独立文档。

旧误报参考保留为可见线索。原型将“明确问题同时命中旧参考”显示为冲突待复核，防止相似描述自动折叠当前问题。不同工况的明确例外由当前证据核验后单独展示。实际语义匹配、自动消解冲突与证据回查属于后续服务接入范围。

规则内容修改后重新验证与审核，已启用版本继续用于新任务。每次试运行保存独立快照；规则修改、停用及人工复核分别记录，历史原始判定可以回看。

## 文件与验证

- `app/web/static/rule-library-prototype/index.html`：独立页面入口。
- `prototype.css`：桌面与移动端布局。
- `model.js`：示例数据、规则生命周期和模拟判定。
- `prototype.js`：页面交互、浏览器存储和记录导出。
- `tests/test_rule_library_prototype.js`：发布门槛、例外与证据、版本快照和反馈边界验证。

```bash
node --test tests/test_rule_library_prototype.js
uv run ruff format .
uv run ruff check .
```
