# 用户权限

## 身份与授权

用户通过当前认证模式建立身份，默认使用自己的任务和模型配置。管理权限直接分配给用户主体，由超级管理员在“用户权限”页签维护。

| 用户来源 | 授权主体 | 生效范围 |
| --- | --- | --- |
| IP | `ip:<客户端IP>` | 使用同一 IP 的访问者共享权限，地址变化后使用新地址的授权 |
| 统一登录 | `cookie_session:<稳定用户ID>` | 姓名、工号、Cookie 和访问 IP 变化后继续使用同一稳定 ID 的授权 |

IP 来源使用 `server.real_ip_header` 指定的请求头或连接地址；启用 `server.proxy_fix` 时连接地址取代理适配后的值。默认直连配置按连接地址识别用户。网关覆盖客户端提交的真实 IP 头，并限制外部直连应用。Cookie 身份建立成功后才读取该用户的授权；身份失效时按统一登录流程处理。

IP 用户和统一登录用户分别授权。任务及模型配置的 IP 归属迁移只处理业务数据，两种身份的管理权限保持各自归属。

## 管理权限

| 权限 | 能力 |
| --- | --- |
| `tasks.view_all` | 查看全部用户的五类任务、详情、状态、模型输出、报告及原始文件；支持报告导出与媒体预览 |
| `tasks.manage_all` | 包含查看权限，可复核、回填报告、取消或重试任务与检查项、删除及批量删除全部用户的任务 |
| `reports.final_review` | 包含查看全部任务权限，可对自己或他人初审不认可的条目逐条终审，访问终审列表及审核记录 |
| `stats.view_all` | 查看全局统计概览和管理任务列表的汇总指标 |
| `rules.manage` | 维护公共检查项、名称、说明、提示词、启用状态和顺序，以及全局误报忽略规则 |

导航直接按授权显示概览、各类任务和公共规则。各类任务的路径保持一致，拥有查看全部任务权限时展示全部用户的任务，其余用户展示自己的任务。刷新页面后按当前授权更新任务范围与操作。只拥有统计或规则权限的用户继续通过任务导航访问自己的任务，模型配置始终按当前用户主体管理。

普通用户的五类任务页面使用 `/`、`/consistency`、`/language-consistency`、`/images` 和 `/videos`。任务详情、下载、媒体和操作接口使用 `/tasks/...`，状态轮询使用 `/task-statuses`，公共规则使用 `/rules`，统计概览使用 `/overview`。页面链接、筛选与操作回跳保持对应的用户路径。

普通用户访问未获授权的概览或规则页面时，按统计、全部任务、规则的顺序跳转到已授权页面；没有额外授权时进入个人任务。任务接口按当前授权限定个人或全部任务，管理他人的任务需要全局管理权限。规则和概览的异步请求及写操作未获授权时返回 403。统一登录身份失效时进入登录流程。

查看全部任务的用户可以操作自己的任务；他人的任务展示只读报告，保留导出、下载和预览，人工反馈以文字展示。全局管理权限同时控制单项操作和批量操作。批量请求先验证全部选中任务的访问权限，再执行删除。

全局统计与全部任务访问分别授权。管理列表中的汇总指标和状态接口中的汇总计数由统计权限控制；任务详情中的报告计数随任务查看权限提供。

终审列表使用 `/final-reviews`，逐条初审、终审和记录统一位于 `/tasks/<任务ID>` 的报告条目，终审提交使用 `POST /tasks/<任务ID>/reviews`。报告及审核记录的查看权限随任务授权提供，初审写入需要任务管理权限，终审写入需要 `reports.final_review`。只有终审权限的用户在同一条目查看初审结果，并对初审不认可的条目填写终审意见。未确认和认可的条目无需终审，已有审核记录仍可查看。有终审权限的用户可以终审自己或他人初审不认可的条目，IP 和统一登录用户使用相同的授权规则。权限在每次提交时检查，撤销后立即停止终审写入。普通用户路径沿用当前用户身份，本地管理员在审核记录中使用 `local_admin:primary` 主体；统一登录的管理员继续沿用其个人主体。每次初审和终审均独立保存人员、时间和结论。

## 超级管理员

超级管理员使用本地 `config.yaml` 中的账号密码独立登录，拥有全部已实现的管理能力。

本地 `config.yaml` 的 `admin_url` 指定超级管理员入口，默认 `/console`。该路径及其页面和接口统一检查超级管理员登录，登录页提供本地账号密码认证。入口在未登录时进入本地管理员登录页；普通用户的管理授权按用户路径生效。超级管理员在 console 入口及其 `/overview` 页面查看概览，日期筛选保持当前页面路径。

超级管理员会话只在配置的管理路径内生效。同一浏览器访问普通用户入口时，导航、统计和任务操作按当前 IP 或统一登录用户的实际授权提供，链接保持普通用户路径；授权撤销在后续请求生效。

以下功能由超级管理员专属维护：

- 系统运行配置：任务并发、文件保留与清理、出站网络、诊断日志及 IP 显示名称。
- 用户授权：查看用户权限列表、分配、替换和撤销管理权限。
- 领域：维护领域标签，为用户选择一个或多个领域。

公共规则使用独立的管理页面，超级管理员也可以在系统设置中维护。权限页展示五项可分配的管理权限。权限保存验证超级管理员登录、页面令牌、目标用户存在性和权限选项，授权变更记录在应用日志中。

## 用户列表与持久化

成功识别的用户登记到 `user_identities(subject, created_at)`。数据库首次建立用户登记表时，从已有任务、模型提供商、IP 显示名称和统一登录资料补齐用户。删除任务后继续保留用户登记。

权限页支持按名称、IP 和身份 ID 搜索用户，可同时筛选领域或“未标记”用户，复用任务表格的每页条数、翻页和页码跳转组件，分页保留搜索与领域条件。统一登录用户取最新身份资料并单行显示，IP 用户显示名称及身份 ID 小字。各权限列通过问号提示说明对应功能。

勾选或取消权限后自动保存。勾选管理全部任务或报告终审时同时勾选查看权限，取消查看全部任务时同时取消管理和终审权限。连续点击按用户逐行顺序保存，以最后一次选择为准；保存失败时恢复最近确认的选项，并通过页面通用提示反馈。

`user_permissions(subject, permission)` 以主体和权限组成主键，权限值限定为五项管理能力。保存管理全部任务或报告终审权限时同时保存查看权限；清空选项后撤销该主体的全部额外管理权限。

每个 HTTP 请求从 SQLite 读取授权，并在请求上下文内复用结果。不同 Web 进程共享同一份授权，权限更新在后续请求生效。活动任务列表检测查看、管理、统计和规则权限变化后刷新页面；任务详情轮询把操作权限纳入版本，模型输出轮询同步操作权限。

console 和普通用户的页面及接口响应使用 `Cache-Control: no-store`，页面与下载内容按当前请求的授权提供。

## 领域标签

超级管理员在“用户权限”表格的“领域”列点击“设置领域”或“编辑领域”，选择已有领域或输入名称添加新领域，点击“保存”提交。一个用户可关联多个领域，移除全部已选领域并保存后显示“未标记”。取消编辑保留已保存的标签；保存失败保留草稿供重试。

勾选多名用户后点击表格上方的“批量添加领域”，选择或新建领域，点击“添加到所选用户”统一保存。表头复选框全选本页用户，查询和翻页后重新选择；可调整每页条数集中处理更多用户。批量添加保留每人的已有领域并合并重复标签，成功后更新各行并清除选择。失败时保留选人和领域草稿。

领域目录在用户之间共享，名称合并多余空白并忽略大小写去重。每个用户最多关联 20 个领域，每个名称最多 40 个字符。取消用户关联后，领域名称继续保留在目录中供复用。

批量接口每次接受最多 200 位用户，在同一事务中检查所有用户及合并后的领域数量，再追加关联。任一用户失效、超出领域上限或写入失败时，整批保持原状。

`product_domains` 保存领域目录，`user_product_domains(subject, domain_id)` 保存用户关联。标签跟随稳定用户主体，身份资料更新后继续保留；IP 用户与统一登录用户分别维护。领域用于用户分类和筛选，管理权限、任务归属和检查规则按各自配置生效。标签与权限独立保存，写入均验证超级管理员登录、页面令牌和目标用户。

## 模块与验证

- `identity/permissions.py` 定义可分配权限和包含关系。
- `persistence/permissions.py` 登记用户、查询授权、保存授权和读取分页用户列表。
- `contracts/user_domains.py` 定义领域名称和数量约束，`persistence/user_domains.py` 保存领域目录与用户关联。
- `web/auth.py` 检查超级管理员、管理权限与任务操作范围。
- `web/permissions.py` 提供超级管理员的权限设置页面。
- `web/settings.py` 分别提供系统设置和公共规则管理入口。

路由授权覆盖页面、轮询、报告导入导出、原始文件、媒体、模型输出和任务操作。任务提交与管理写操作使用浏览器控制、页面脚本无法自行设置的 `Sec-Fetch-Site` 判断同源关系。`same-origin` 支持代理前后的协议与主机差异；`same-site` 和 `cross-site` 返回 403，`Origin: null` 返回 403。请求缺少明确的同源标记时，携带的 `Origin` 与后端识别的来源精确比较；两种头均缺失时保持非浏览器客户端的调用兼容。来源校验与用户身份、权限和页面令牌校验分别执行。`tests/test_permissions.py` 验证默认业务访问、两种身份隔离、查看与管理范围、批量越权、专属功能、页面令牌、反向代理后的任务提交、跨站请求、权限撤销、IP 数据迁移和已有用户登记。

`tests/test_permissions_ui.js` 使用 Node.js 验证勾选联动、自动保存、连续点击、失败恢复与多用户独立保存。`tests/test_task_list_ui.js` 验证权限变化后的手动刷新与页面同步。

`tests/test_user_domains.py` 验证领域复用、输入约束、身份隔离、独立保存、事务回滚、筛选分页及数据库初始化。前端组件与浏览器测试覆盖标签编辑、失败重试、取消请求、刷新保留和移动端操作。

```bash
uv run python -m unittest tests.test_user_domains tests.test_permissions tests.test_cookie_session_routes tests.test_routes tests.test_architecture
node --test tests/test_permissions_ui.js tests/test_task_list_ui.js
```
