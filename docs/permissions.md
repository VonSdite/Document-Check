# 用户权限

## 身份与授权

用户通过当前认证模式建立身份，默认使用自己的任务和模型配置。管理权限直接分配给用户主体，由超级管理员在“用户权限”页签维护。

| 用户来源 | 授权主体 | 生效范围 |
| --- | --- | --- |
| IP | `ip:<客户端IP>` | 使用同一 IP 的访问者共享权限，地址变化后使用新地址的授权 |
| 统一登录 | `cookie_session:<稳定用户ID>` | 姓名、工号、Cookie 和访问 IP 变化后继续使用同一稳定 ID 的授权 |

IP 来源使用 `server.real_ip_header` 指定的请求头或连接地址；启用 `server.proxy_fix` 时连接地址取代理适配后的值。默认直连配置按连接地址识别用户。网关覆盖客户端提交的真实 IP 头，并限制外部直连应用。Cookie 身份建立成功后才读取该用户的授权；身份失效时按统一登录流程处理。

IP 用户和统一登录用户分别授权。任务及模型配置的 IP 归属迁移只处理业务数据，两种身份的管理权限保持各自归属。

## 管理权限

| 权限 | 能力 |
| --- | --- |
| `tasks.view_all` | 查看全部用户的五类任务、详情、状态、模型输出、报告及原始文件；支持报告导出与媒体预览 |
| `tasks.manage_all` | 包含查看权限，可复核、回填报告、取消或重试任务与检查项、删除及批量删除全部用户的任务 |
| `stats.view_all` | 查看全局统计概览和管理任务列表的汇总指标 |
| `rules.manage` | 维护公共检查项、名称、说明、提示词、启用状态和顺序，以及全局误报忽略规则 |

导航直接按授权显示概览、各类任务和公共规则。拥有查看全部任务权限时，各类任务导航进入全部用户的任务列表；其余用户的任务导航进入自己的任务列表。只拥有统计或规则权限的用户继续通过任务导航访问自己的任务，模型配置始终按当前用户主体管理。

查看全部任务的用户可以操作自己的任务；他人的任务展示只读报告，保留导出、下载和预览，人工反馈以文字展示。全局管理权限同时控制单项操作和批量操作。批量请求先验证全部选中任务的访问权限，再执行删除。

全局统计与全部任务访问分别授权。管理列表中的汇总指标和状态接口中的汇总计数由统计权限控制；任务详情中的报告计数随任务查看权限提供。

## 超级管理员

超级管理员使用本地 `config.yaml` 中的账号密码独立登录，拥有全部已实现的管理能力。以下功能由超级管理员专属维护：

- 系统运行配置：任务并发、文件保留与清理、出站网络、诊断日志及 IP 显示名称。
- 用户授权：查看用户权限列表、分配、替换和撤销管理权限。

公共规则使用独立的管理页面，超级管理员也可以在系统设置中维护。权限页只展示四项可分配的管理权限。权限保存验证超级管理员登录、页面令牌、目标用户存在性和权限选项，授权变更记录在应用日志中。

## 用户列表与持久化

成功识别的用户登记到 `user_identities(subject, created_at)`。数据库首次建立用户登记表时，从已有任务、模型提供商、IP 显示名称和统一登录资料补齐用户。删除任务后继续保留用户登记。

权限页支持按用户来源和姓名、工号、IP、稳定 ID 筛选，并提供分页。统一登录用户的展示资料取最新身份资料，IP 用户使用设置的显示名称。

勾选或取消权限后自动保存，每行显示保存状态。勾选管理全部任务时同时勾选查看权限，取消查看全部任务时同时取消管理权限。连续点击按用户逐行顺序保存，以最后一次选择为准；保存失败时恢复最近确认的选项，并提示刷新确认后重试。

`user_permissions(subject, permission)` 以主体和权限组成主键，权限值限定为四项管理能力。保存管理全部任务权限时同时保存查看权限；清空选项后撤销该主体的全部额外管理权限。

每个 HTTP 请求从 SQLite 读取授权，并在请求上下文内复用结果。不同 Web 进程共享同一份授权，权限更新在后续请求生效。活动任务列表检测管理和统计权限变化后刷新页面；任务详情轮询把操作权限纳入版本，模型输出轮询同步操作权限。

管理端响应使用 `Cache-Control: no-store`，页面与下载内容按当前请求的授权提供。

## 模块与验证

- `identity/permissions.py` 定义可分配权限和包含关系。
- `persistence/permissions.py` 登记用户、查询授权、保存授权和读取分页用户列表。
- `web/auth.py` 检查超级管理员、管理权限与任务操作范围。
- `web/permissions.py` 提供超级管理员的权限设置页面。
- `web/settings.py` 分别提供系统设置和公共规则管理入口。

路由授权覆盖页面、轮询、报告导入导出、原始文件、媒体、模型输出和任务操作。管理写操作校验浏览器提供的 `Origin` 和 `Sec-Fetch-Site`，跨站请求返回 403。`tests/test_permissions.py` 验证默认业务访问、两种身份隔离、查看与管理范围、批量越权、专属功能、页面令牌、跨站请求、权限撤销、IP 数据迁移和已有用户登记。

`tests/test_permissions_ui.js` 使用 Node.js 验证勾选联动、自动保存、连续点击、失败恢复与多用户独立保存。

```bash
uv run python -m unittest tests.test_permissions tests.test_cookie_session_routes tests.test_routes tests.test_architecture
node --test tests/test_permissions_ui.js
```
